# W1-r2 delivery — hosted selection + fail-closed sanitizer

## Root causes

First-round source load was correct (preview URL, no empty-ready). Parent r2 found the remaining W1 gaps:

1. **Sanitizer.** The Node test path had treated an unsupported DOMPurify as “return the HTML”. Parent already switched that to throw. This round keeps fail-closed: no raw HTML fallback, real DOMPurify under JSDOM, and negative tests for an unavailable sanitizer.
2. **Typecheck.** `ok` was written twice when spreading a loaded Word result; `isSupported` was read from a union that did not declare it; an optional rendition URL was passed into `isArtifactSourceTreeUrl`.
3. **Hosted commands.** `dispatchRichDocHostedCommand` was a singleton with no production caller. The agent surface accepted arbitrary JSON and called it success. `RichDocHostedRoute` did not listen for `selection-changed` or bind `SelectionToolbar`.
4. **Sandbox compile.** `hosted-editor-iframe-sandbox-render` stubbed `workbench-routes` without `officeExtensionForItem`, so the document iframe case failed to compile. Origin/sandbox assertions were already correct.

## Chrome path (normal vs pro)

The host edit bar is only on the artifact/「编辑」 page (`editBarVisibleOnPage` is artifact-only). The Umo page hides that bar and shows Umo’s own toolbar (`hide-chrome` is false in pro).

`next` still mounts `RichDocHostedRoute` for both pages. **Supported L1 path is normal hosted mode:** after the document is ready and writable, the route binds `RichDocHostedContextToolbar` → `SelectionToolbar`, listens for `selection-changed` / `selection-result`, and sends a typed `selection-command` with envelope `origin: "user"`. Pro stays on Umo’s native toolbar. W5 does not need to finish this route.

## Fixes

- `sanitizeRichDocHtml` binds DOMPurify to `window` when needed and throws if sanitize is missing, unsupported, or not a string. Load/import use that path; tests may inject a sanitizer, never a raw-HTML fallback.
- Word hosted load returns a single `ok: true` object. Sanitizer types are one shape. Source-tree URL checks only run on a real string.
- Removed the unused sink registry. Host send uses `normalizeSelectionCommand`, the closed Umo control set (`bold` / `italic` / `heading` / `list` / `link` / `color`), and `SelectionCommandGate`. Malformed, stale, read-only, and unknown controls fail. Agent commands omit the human origin stamp and report review, not apply. Human clicks stamp `origin: "user"`.
- Document iframe sandbox test stubs `officeExtensionForItem` and the new toolbar; sandbox token assertions are unchanged.

Integrity, CAS, origin, and permission checks were not loosened. umo-hosted was not modified.
