# W2-r2 delivery — keep snapshot saves on the owned session

## Root causes

1. `saveSnapshotWithConflictRetry` issued a second `saveSnapshot` after the first result. Round 1 treated `first.stale` as retryable and used `first.session.id` as a new `expectedSessionId`, which can write an old document into a new conversation. Parent patched stale/cross-session, but the extra retry was still redundant: `WorkspaceSession.saveSnapshot` already merges and retries its own same-session 409 once when `mergeFromLatest` is passed (lines 503–727). `writeOwnHistoryEntry` still retried stale onto `latest.id`.
2. The dedicated (non-embedded) merge ignored `latest` and replaced the snapshot with a fresh `advancedSessionSnapshot`, dropping concurrent unrelated keys on the same session.
3. `createArtifactRevisionStore` had no production consumer (only a public export and bus-only tests). Mapping HTTP 409 before `integrity-failed` would have called a CAS conflict a payload that must not be replayed.

Integrity / CAS / size / digest / MIME checks from round 1 were not loosened. Operator artifact `21c1e4d9-0818-4bbe-ae33-b4d01a5beafd` was not mutated.

## Fix

- One owned `saveSnapshot` call via `saveOwnedWorkspaceSnapshot`. `mergeFromLatest` is still passed so `WorkspaceSession` can do its same-session 409 merge. Stale, read-only, and `conflict.latest` from another session never get a second write.
- Dedicated merge is `mergeAdvancedSessionSnapshot`: spread latest, then overlay this editor’s advanced-session fields. Embedded merge stays `withInlineEditorHistoryHead` / `withInlineEditorHistoryEntry`.
- `writeOwnHistoryEntry` no longer retries stale onto the newly active session.
- Deleted the unused artifact CAS adapter, its public exports, and `tests/W2-plugin-store-artifact-cas.test.mjs`. Restored the plugin-store contract comment that this adapter is unimplemented. Shared `withRecovery` / memory-store conflict disposition used by acceptance tests is unchanged.
