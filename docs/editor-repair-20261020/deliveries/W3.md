# W3 delivery — global icon chrome, My library, share/favorite

## Root causes

1. Host first row (`AdvancedWorkspaceActionBar`) painted labeled 素材库 / 我的库 / save-state text. The library preview header is icon-only (download / share / star).
2. Share and favorite already exist on `ArtifactActions` + `setArtifactFavorite`. Editor chrome never received the open `LibraryItem`, so those actions were missing from the editor top row.
3. `InlineAdvancedWorkbenchShell.openLibraryPanel` only fell back for `materials` when SplitWorkspace was absent. `mine` was a no-op on library-standalone / `/advanced/...` pages, so 我的库 did nothing.
4. Plugin self chrome (`PluginChromeFrame` default) did not host library buttons or item-identity share/favorite. Host chrome correctly leaves that to the parent row.
5. Save failure was visible red sentence copy on the cloud control. It belongs on `title` / the retry menu, with status still in `sr-only` for the screen reader.

Integrity / CAS / origin / permission checks were not loosened. Favorite still requires a durable item with `canFavorite` and `integrity.ok`, and checks the returned `artifactId`/`revisionId`.

## What users get

The editor top row matches the preview: outline icons, 44px hits, accessible names via `aria-label` / `title`. 素材库 and 我的库 still say those names to assistive tech. Share copies a URL that carries `item=<artifactId>`. Favorite calls the real `setArtifactFavorite` API. On a page without SplitWorkspace, 我的库 opens a side list of `listMyArtifacts` and does not unmount the editor. Extracted plugins using self chrome get the same mine / share / favorite row.
