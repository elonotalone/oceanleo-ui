# W5-r3 delivery — hosted toolbar hold reaches the real send path

## Root causes

W5-r2 bounded `SelectionCommandGate.lastContext` to `holdInteraction`, but the hosted owners never called it.

1. **workbench-embed.** Toolbar press blurs the iframe. `selection-changed(null)` sets `latestSelectionRef` to null. `accept(command, null)` rejected. `iframe.onBlur` also called `cancelAll`, wiping any in-flight gesture.
2. **RichDocHostedRoute.** The same blur replaced the live range with `richdoc-caret` via `hostedSelectionForToolbar(null)`, so a selected-range command could retarget the caret.
3. **EmbeddedRoute.** `onSelectionChange(null)` unmounted `SelectionToolbar` before click unless the route also kept the held range.

Integrity, CAS, origin, sandbox, and permission checks were not loosened. Agent commands still omit `origin: "user"` and still go through review.

## What users get

A shared-bar press against a hosted editor keeps the exact selected object/range through iframe blur. Bold (and the rest of the live controls) reaches `sendToEditor` with that selection/revision and a human `origin: "user"` stamp. After release, a later matching command is rejected. Switching document, unmounting, or a genuine new selection clears the hold. Another popover cannot keep this session.

## What changed

- New scoped interface: `onSelectionInteractionChange(heldSelection | null)` on `SelectionToolbar`, fired synchronously on pointerdown / Enter / Space. Passed through `EmbedEditorPane.selectionInteractionRef` and RichDoc’s hosted toolbar.
- Each owning gate calls `holdInteraction` before the blur message; `releaseInteraction` on release, unmount, item/revision/instance reset, and a genuine new selection.
- `reconcile(null)` while held does not cancel the active toolbar transaction. A real new object/revision ends the hold and rejects the old command.
- Embed mutating send stamps `origin: "user"` only on the toolbar-driven `selection-command` path. Reconcile/cancel posts stay unstamped.
- Richdoc uses the held range instead of the caret fallback for that press.
- Deck has no shared toolbar (`DeckHostedContextToolbar` does not exist). Send still prefers live selection; a new live selection or document identity clears any hold leftover.
