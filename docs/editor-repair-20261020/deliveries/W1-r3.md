# W1-r3 delivery — verified load vs visible-body

## Root causes

Readiness after r1/r2 still inferred a missing source by stripping HTML tags and requiring text / `richDocHasContent`. A successfully fetched image-only HTML document (parent repro: artifact `00000000-0000-4000-8000-000000000001`, `scan.html`, `<p><img … alt="扫描页">`) was rewritten to `source:empty` with “revision 缺少可验证的 source/full”. The same gate rejected a valid empty DOCX or persisted empty native JSON after a deliberate deletion.

Failed loading (missing URL, network/parser/sanitizer, source-tree-only, unknown `{}` project, empty project hiding a failed original) was already supposed to stay blocked. The bug was using visible text as a proxy for “the loader succeeded”.

## Fixes

- `richDocHtmlHasBody` treats `img` / `picture` / `svg` / `video` / `table` / `figure` (and remaining text) as a body. Tag-stripped length is only a fallback after those nodes.
- `richDocLoadVerified` is `source !== "empty" && !error`. A verified fetch/parse is a loaded document even when the body is image-only or intentionally empty.
- `admitRichDocEditorSource` is the hook/pro gate: verified load or a new blank draft; an existing artifact with `source:empty` still fails.
- Empty project JSON uses `resolveRichDocProjectAgainstOriginal`: richer original wins; valid empty native JSON is kept when it is the document; a distinct original that failed stays blocked; `{}` is not a document.
- Hosted JSON/HTML/DOCX admission uses the same helpers. Empty inline handoff no longer hides a richer original.
- Node Mammoth accepts `buffer` (browser still gets `arrayBuffer`), so image-only Word is parsed in tests and SSR.
- Sanitizer remains fail-closed. Integrity / CAS / origin / permission checks were not loosened. Zero-byte server integrity is unchanged. Load still resets dirty; `setContent(..., { emitUpdate: false })`; persist still requires `dirty && sourceReady`.
