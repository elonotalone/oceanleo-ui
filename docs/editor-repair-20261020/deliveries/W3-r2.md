# W3-r2 delivery — usable library chrome, slots, feedback, stretch

## Root causes

1. Standalone My library listed titles only. `InlineEditorMinePanel` had no activation, so a click could not open another artifact.
2. Share/favorite sat in the `download` slot because `GLOBAL_ROW_SLOTS` did not name them.
3. Clipboard share was silent. A favorite request that finished after unmount or item change could still flip the new star.
4. Invite/replay still used labeled glyphs; outer `CollabActionSlot` hid the words with `text-[0px]`.
5. W4 stretch stopped at SplitWorkspace. Standalone fallback aside / PluginThemeScope / Frame panel body still used leftover `overflow-y-auto` as the scroller, so empty and long conversations could not fill the pane.

Integrity / CAS / origin / permission checks were not loosened. Favorite still requires a durable item with `canFavorite` and `integrity.ok`, and checks the returned `artifactId`/`revisionId`.

## What users get

- Mine list rows are buttons. Clicking a *different* item hands off autosave through `leaveAdvancedWorkbench`, then dispatches the existing `intent: "edit"` workspace action and remembers library identity. Clicking the current item only closes the panel. The editor `onClose` is not called on switch.
- Share and favorite have their own first-row slots on host and self chrome. Icons stay outline, 44px, accessible names, pressed/busy/disabled. No extra labeled copies at narrow width.
- Share writes a stable `item=<artifactId>` URL (same identity key ArtifactActions already uses) and toasts `已复制` after clipboard success. Native share sheet is left as-is.
- A favorite in flight cannot update a newly opened item or an unmounted row.
- Invite/replay are the same outline icon set with accessible names; the real invite dialog and replay panel still run. The CSS hide workaround is gone.
- Standalone fallback pane and Frame panel body apply `AGENT_CONVERSATION_HOST_STRETCH_CLASS`. Control-panel overflow stays until a `[data-agent-conversation]` child is present.
