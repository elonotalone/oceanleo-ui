# W5-r2 delivery — bound selection lifetime, drop unused bus

## Root causes

1. `EditBarCommandDispatcher` had no production caller. It was a parallel command bus. Handler exceptions were swallowed and async rejections were unhandled. The live toolbar already calls the route `onCommand`.
2. `SelectionCommandGate.lastContext` survived `reconcile(null)`, `cancelAll`, and a later `accept(command, null)`. A cleared or switched document could authorize a matching command indefinitely. The first-round “blur hold” was too wide.
3. `useEditBarSelectionSession` polled any `[data-anchored-popover]` every 50 ms and never cleared the timer. Another overlay could keep an old toolbar selection mounted.

Integrity / CAS / origin / permission checks were not loosened. Revision, epoch, transaction, and request-id dedupe stay strict.

## What users get

Toolbar pointer/keyboard still keeps the current object for that press (Bold, stepper, More, portaled select). After a genuine clear, document switch, or release, a delayed matching command no longer retargets the old object. Another popover cannot keep this bar’s session alive.

## What changed

- Deleted `src/shell/edit-bar-command-dispatch.ts`. Bus-only tests removed.
- `lastContext` is used only while `holdInteraction()` is active. `reconcile(null)` without a hold, `cancelAll`, `clear`, and `releaseInteraction` wipe it. `accept` / `reconcile` / `cancelAll` / `clear` signatures are unchanged.
- Session hold is event-driven: pointerdown + Enter/Space, one-shot `setTimeout(0)` on pointerup/cancel/focusout, overlay-state `MutationObserver` filtered to this `data-edit-bar-session`. Timers and observer disconnect on unmount. More and select popovers carry the session id. Number/text inputs still take focus.
- Kept first-round preserve-on-pointerdown and Fabric effect tests.
