# W5 delivery — shared edit bar commands

## Root causes

1. Compact edit-bar controls did not `preventDefault` on pointerdown. The inspector already did. Pressing Bold (or More, a select option, undo) stole focus from same-document cores and collapsed the range.
2. Hosted iframes emit `selection-changed(null)` as soon as the host bar is pressed. `SelectionCommandGate.accept` then rejected the click because `context` was null, even though the command still named the last selection.
3. `SelectionToolbar` dropped to `null` the moment live context cleared, so compact buttons unmounted before `click`.
4. Undo/redo on the bar were click-only. With focus on a font-size field, Ctrl/⌘Z undid the input instead of the document.
5. There was no shared handler lifecycle for late-ready / async hosted commands. Existing cores stay; W5 added a dispatcher they can register with. The live toolbar still calls the route `onCommand` so existing adapters keep their own apply path.

Integrity / CAS / origin / permission checks were not loosened. A different selection id or revision is still rejected.

## What users get

Pressing a shared edit-bar control keeps the current object/range and actually runs that control. Bold toggles the selected text. The font-size stepper changes size. Ctrl/⌘Z from the bar undoes the document. A hosted editor that blurs when the bar is pressed no longer loses the command if the last selection still matches.

## Gaps / parent requests

- W1: Umo / richdoc apply still lives in W1 files. If a handler uses `chain().focus()` after a lost range, it must restore the range itself. Generic toolbar now avoids stealing focus.
- W6: Per-plugin adapters (Deck, PDF, Univer, designcombo, …) must still apply the command they receive. If a hosted core clears selection on blur and then ignores `selectionId`, that is adapter work. They can register `EditBarCommandDispatcher` for late-ready / in-flight async; W5 did not edit routes.
- Parent: `workbench-embed.tsx` already uses `SelectionCommandGate`. It now keeps last non-null context automatically. No child edit.
- Number/text fields on the bar still take focus so a value can be typed.
- Animation-gallery popovers were not given a second pointerdown hook; in-tree capture covers them, portaled ones rely on the hold + last-context gate.
- `WorkspaceSelection.tsx` is workspace-list state, not editor selection. Left untouched.
