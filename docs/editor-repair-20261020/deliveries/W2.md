# W2 delivery — UI↔gateway persistence contract

## Root causes

Screenshot save (`提交新版本` → `保存被拒绝（integrity-failed）`) had three shared roots. None of them is “convert failure to success”.

1. **Inspect treated missing Storage size as a corrupt blob.** `_inspect_owned_object` used `int(info.get("size") or info.get("contentLength") or 0)` and raised integrity-failed when that was 0, before hashing. Supabase often only fills `metadata.size` (media_rehost already reads that). The generic Chinese fallback `保存被拒绝（integrity-failed）` is `_wire_user_message` for English size/capability errors. `already_owned` then re-parsed the URL against `media-uploads` only, ignoring `result.object_key`.
2. **Autosave retried invalid payloads.** `AdvancedPersistenceController` / draft controller auto-retried every throw, including integrity-failed. That masked bad bytes as a transient loop.
3. **Save confirmation (`record-saved-item`) did not merge on session CAS.** Parent logs 12:45:33–12:46:02 UTC (`AdvancedContentWorkbench.tsx` ~639, `AutosaveRejected`) are this second surface. `writeOwnHistoryEntry` already passed `mergeFromLatest`; `recordSavedItem` did not, so a successful commit could still loop on snapshot conflict.

Plugin-store artifact revision CAS was documented and unimplemented. Mapping 409 and integrity-failed both to `conflict` would have invited overwrite-after-re-read; integrity-failed is now `failed`.

Operator artifact `21c1e4d9-0818-4bbe-ae33-b4d01a5beafd` was not mutated.

## Fix

- Wire inspect: `metadata.size`, hash actual bytes when size is unknown, fail only if the stream is empty/oversize/mismatch; inspect approved buckets; `already_owned` uses `object_key`.
- Upload verify (`prepare_upload_blob` / `verify_blob_durable`): same size helper; hash still has to match the declared digest and byte_size.
- Capability MIME mismatch stays integrity-failed, with `receivedMediaType` so the user copy is Chinese and specific.
- Persistence: do not auto-retry integrity-failed / permission / identity failures. Drafts stay unacknowledged. Transient network still retries. Explicit `retry()` can reuse a committed item after session CAS.
- `recordSavedItem` retries once against the latest snapshot on conflict; hard snapshot refusals are not tagged retryable.
- Empty SHA-256 is refused locally so a blank load cannot overwrite existing bytes.
- Artifact CAS adapter: 409 → conflict, integrity-failed → failed, `canEdit` false → denied; `withRecovery` keeps the draft on throw.
- Successful `createArtifactRevision` still requires a new `revisionId` on the same root with `integrity.ok` and pins `previous_revision_id`.
