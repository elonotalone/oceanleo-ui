# W6 delivery — non-richdoc editor source / save mapping

## Root causes

Operator screenshots are richdoc/Umo (W1/W2). The same integrity failure exists on other adapters: a load miss became an editable empty document, `dirty` turned true, autosave submitted blank bytes over the existing artifact.

Owned evidence:

1. **Grid.** `loadGridSheets` returned `[emptyGridSheet()]` when a durable artifact had no workbook URL. Catch paths installed that empty snapshot as converted + `snapshotReady`, so autosave could run. `gridOpenFailedClosed` now refuses `empty` when a source was expected; durable missing source throws.
2. **Website / design local.** Parse failure or a durable item without inline source still opened `blankWebsiteSource` / the unowned design hook’s blank canvas, and flush returned `{ ok: true }`.
3. **Image.** Route `flush` / background persist called `editor.save()` while `loading` or `sceneDiagnostic` was set. The unowned hook clears `sceneDiagnostic` at the start of save, so a failed layered scene could be written as a blank canvas. Route now refuses before `save()`.
4. **PDF / audio / 3D / chart next / video-timeline / deck.** Persistence `dirty` / `autoSave` / `recovery.ready` were not always gated on bytes, capture, `modelLoaded`, `sourceReady`, or `sourceFailed`.
5. **Game.** A durable artifact without a playable envelope rendered “generate first version” and could persist a new envelope onto the existing identity.

Integrity, CAS, origin, and permission checks were not loosened. Loading failure never becomes a successful blank save.
