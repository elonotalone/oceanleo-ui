# W3-r3 delivery — /library item activation and native collab triggers

## Root causes

1. Portal `/library` mounts `ArtifactLibrary` wrapping `MyLibrary` with no `action`. r2 made mine rows dispatch `WORKSPACE_ACTION_EVENT` (`tab: "mine"`, `intent: "edit"`), but that page had no receiver. ResultCanvas already feeds `action`; the screenshot path does not.
2. Invite/replay still had two DOM triggers: a visible outline proxy plus a hidden original button clicked via `querySelector`. Screen readers and tests saw duplicates; the CSS hide workaround was already gone, the duplicate-trigger hack was not.

Integrity / CAS / origin / permission checks were not loosened. Owner/private projection and original type filters are unchanged. Tests mock IM/grant/replay services and do not send messages or create replays.

## What users get

- On `/library`, while editing item A, clicking item B in 我的库 hands off autosave, then the still-mounted MyLibrary opens B. Clicking the current item only closes the side panel.
- Invalid envelopes (wrong tab, `intent: "open"`, missing nonce or itemId) are ignored. Unmounting the page removes the listener.
- Invite together and generate replay in the first-row collab slot are each one 44px outline IconButton. Clicking invite opens the real conversation dialog. Clicking replay opens the range panel; clicking again closes it. Labeled buttons elsewhere stay labeled (`iconOnly` defaults false).
- Share/favorite slots, stretch, toast, and race guards from r1/r2 remain.
