# W6-r4 delivery — remaining plugin positive load / mutate / reopen

Parent stub `96bf746a` recorded a helper-level reopen for these families. That is not V1 (a): it never ran `buildPdfCommandSurface`, `createAudioCommandSurface`, `createVideoCommandSurface`, `createModel3DCommandSurface`, or the shown `workflow.add-node` run. This commit does.

Original W6 ownership respected. No W1 richdoc, W2 save/session, W3 chrome, W4 chat, W5 SelectionToolbar, or ComputerDock edits. No pptist-hosted / website / video repo edits. Integrity, CAS, origin, sandbox, and permission checks were not loosened.

## Root causes

1. **PDF / audio / video-timeline / 3D.** Host models and bar command surfaces already existed. Existing tests used recording doubles or model helpers (`rotatePdfPage` / `patchClipIn`) and never drove `surface.run` on a live port, so a blank or no-op command could still look green.
2. **Video-canvas.** The shown 加节点 button and `workflow.add-node` both called `addVideoCanvasNode` inline. W6-r2 proved the helper, not the same `run` the stage uses.
3. **Game play.** Hosted sandbox iframe only. There is no host edit model. A fake serialize-reopen would be a lie.
4. **Game code.** Envelope + agent surface already park writes without a review token. That is the host-side proof, not play-preview editing.

Loading failure still never becomes a blank save over existing bytes.
