# Editor layout and save result — 2026-10-21

## Findings

- The shared persistence controller defaulted to a 1.6s quiet window. It now uses 500ms; the saving state still begins on a real user edit and remains pending until the saved item or draft pointer has received its session receipt. Initial/hydration-only dirty observations remain excluded, and in-flight revisions remain serialized.
- The Fabric image editor only had the full publication path for its shared save hook, making routine edits wait on export/publication work. It now captures a revision-bound Fabric project into the existing durable server draft tier (`oceanleo.fabric-image.edit.v1`); the inner project remains `oceanleo.fabric-image.v1`. The existing recovery loader validates the draft pointer and routes the payload through `restoreRecovery`, so returning to the item restores the server receipt. Draft acknowledgement does not create a published version.
- Panel open/close changed available canvas width without preserving the view consistently. Both the extracted `PluginChromeFrame` and the standalone `InlineAdvancedWorkbenchShell` now animate panel width/flex-basis/opacity while retaining the closing content subtree through the 300ms exit. The image route uses the inline shell. `SplitWorkspace` was inspected: its app/library pane basis is controlled by the stable `ratio`; opening a detail replaces content inside the already allocated left pane and does not change its width, so no additional host transition is needed.
- Image canvas container resize now preserves the affine viewport transform and the scene point at the viewport center for custom zoom/pan. Fit-mode documents still refit. Zoom surfaces are 40px high while their hit targets remain 44px.
- `PluginChromeFrame`'s edit-bar host is now zero-height with an absolute 40px sentinel/drop target; the AI button is passed in the shared gesture layer's trailing slot, including the inline bootstrap fallback.

## Recovery regression follow-up

- The initial full regression exposed that the recovery runtime fixture no longer modeled the shared person-edit generation gate, and that a genuinely restored local emergency record needed its own narrowly-scoped promotion signal. Ordinary dirty hydration and server draft restoration remain excluded.
- `use-advanced-recovery.ts` now publishes a promotion only after a successful local emergency restore changes the editor revision. `advanced-draft-recovery.ts` carries the exact key/revision/updatedAt plus a monotonically increasing token. `use-advanced-autosave.ts` only treats a marker created after this editor lifetime mounted as a recovered revision; save operations pin the marker identity and only clear it after a durable receipt covers the latest revision. A later token cannot be cleared by an older in-flight receipt, and a newer receipt can clear an older revision marker even when it is not an exact revision match.
- Focused fixtures were corrected for the new 500ms no-draft default; image-route schema checks now inspect the persistence contract where the schema is defined; image-history mocks include viewport dimensions and await Fabric's async undo; plugin-chrome route mocks include the added capability exports.
- Added/updated regression coverage in `advanced-persistence-controller.test.mjs` and `advanced-recovery-hook-runtime.test.mjs` for exact local recovery promotion, rev1 recovery followed by rev2 edit/receipt, once-only remount behavior, and protection of a newer recovery token. The parent requested these suites plus `e6-autosave-draft-tier.test.mjs`, `image-route-merge.test.mjs`, `rebuild-image-save-history.test.mjs`, `plugin-chrome-edit-bar-page-gate.test.mjs`, and `plugin-chrome-save-menu.test.mjs` for final rerun.

That controller then observed the new item lifetime's clean revision `0` and its drain flushed the already-saved document again. `use-advanced-autosave.ts` now keys background handoff/takeback by the source item identity (source/key/id/url/revision IDs) as well as the material key, so a new saved-item lifetime cannot adopt the old document's flush closure. The recovery fixture now passes its item as the production shell does and asserts the one-creation/remount behavior.
