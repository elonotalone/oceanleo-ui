# W09 — Website: Puck composed normal mode + Puck default UI as Pro

Goal: normal mode is our light editing UI composed from Puck's own composition API on the same Puck
instance (`<Puck>` children with `Puck.Preview`, `Puck.Fields`, etc. — read
`node_modules/@puckeditor/core` types for 0.23): select a block, change text/images, reorder, add/remove
sections — no Puck header/sidebars. Pro = Puck's default full UI on the same data (same instance or same
data object; switching never converts). Saving/publishing/undo only through the OceanLeo top bar;
hide Puck's own publish button/header actions in both modes. Theme with OceanLeo tokens; no Puck branding.
Source-code website projects (`websiteProUnavailableSourceProject`) keep their current behavior; Pro
unavailable reason stays.
Owned cluster: `advanced-routes/WebsiteLocalRoute.tsx`, `src/shell/website-local/**`,
`website-source-carrier/**`, website tests. W01 owns the Pro allowlist (website is on it) and routing.
Acceptance: focused website tests green; tests proving normal mode renders no Puck default chrome and Pro
renders it on the same data, and that Puck's own publish action is not exposed.
