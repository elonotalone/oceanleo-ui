# Hosted video private staging decision

Outcome: editing an existing private Library workflow must not publish its source or previews to a public bucket, nor create temporary Library roots on every autosave.

## Candidate chains and selected boundary

1. Existing URL-only `uploadFile(registerAsset:false)` → public media upload → typed revision. Mature and already wired, but violates the private-file boundary. Rejected.
2. Existing `privateUpload:true` → private typed upload root → source access grant URL → URL-only revision. Uses mature helpers, but `file.url` is deliberately empty; reconstructing URLs/rehosting risks public copies, and each autosave would add temporary Library roots. Rejected.
3. Existing private multipart upload with a narrow `register_asset:false` staging-only branch → existing typed `blob_id` revision adapter → server owner/hash/CAS checks. Selected. No new endpoint, auth mechanism, process, timer, public URL or token forwarding. Small JSON/PNG staging is capped by the existing 20MB private-upload limit. Browser/client holds only a bucket-bound owner locator, digest, MIME and size; these are untrusted hints, not permission. Server storage verification remains final authority.

The returned locator is explicitly `project-assets:u/<owner>/...`; the revision adapter inspects only that private bucket and asserts it is not public, never searching an equivalent key in the public bucket. The default private-upload registration behavior is unchanged. Staging-only validates JSON/PNG and skips typed registration entirely, so it creates no Library root. Saved workflow JSON contains neither staging metadata nor runtime receipt/grant/blob URLs. The iframe's existing artifact-updated envelope retains the opened HTTP URL only as an unused compatibility pointer; a strict video-v2 private descriptor branch supplies source/preview bytes to the existing typed revision protocol.

## Disposable-alias lifecycle

The repository copies committed source/preview bytes into immutable CAS. Retaining the incoming upload aliases forever would accumulate invisible quota usage. Staging-only inputs now use the reserved, server-selected `u/<owner>/editor-staging/YYYY-MM-DD/` namespace; ordinary private uploads cannot enter it. Before private uploads, a bounded collector examines oldest days/files first, considers at most256 aliases older than24hours, reads every exact `artifact_blobs` reference before removal, and excludes referenced/invalid/current objects. Bucket must be confirmed private. Canonical CAS and ordinary user upload namespaces are never candidates. Daily server-selected paths prevent new writes into a concurrently swept expired day. Failed listing/reference checks retain candidates and fail closed before quota.

Focused lifecycle/private-upload tests passed **23/23**. A real non-destructive collector run using a simulated expired cutoff found2 current test aliases, zero references, zero deletions. The full reused-fixture proof then passed with head **`58d052ec-39ed-44a1-b846-df9f316eb390`**, all three media exact and a simulated-expiry dry-run of4 aliases/0 deletions. An intervening attempt advanced the private test fixture to `e9bcf87d-e7a8-4b61-ac29-345afbd7201a` but hit an APIError during verification; it was not counted as a full pass. No additional Library root or original-file edit resulted. No live object removal was performed; removal/reference negatives are unit-tested.

The existing private quota counter enumerates owner upload aliases rather than all historical CAS claims. That platform UC-5 accounting limitation is not represented as fixed. A read-only owner-claim→private-blob join probe timed out57014; it was rejected before implementation (no unproven query, new quota ledger or migration added). The collector's new availability dependency on bounded listing/reference reads is fail-closed and recorded here.

Narrow accounting preservation decision: expiring aliases must not make retained video revisions free of the existing upload cap. Three options were checked: retain every alias (invisible unbounded intermediates), an inner/filter aggregate join (real probe timed out57014), and owner-first bounded FK left-embedding (real single-row probe passed in30ms). The last is selected solely as an additional quota floor: use max(existing owner-prefix private usage, distinct owner-claimed private CAS bytes), avoiding double charging ordinary upload aliases while keeping retained versions counted after expiry. This changes no price/limit, adds no migration/ledger/auth and claims no full UC-5 repair. The helper must paginate owner-first in stable SHA order, fail closed on missing/truncated evidence, and verify the actual owner probe plus expiry-accounting regression before acceptance.

This floor is deliberately not an exact physical-byte union: disjoint/unclaimed legacy or failed-upload objects plus retained CAS may be undercounted by max. That pre-existing platform-accounting limit remains explicit; no claim of general quota repair is made.
