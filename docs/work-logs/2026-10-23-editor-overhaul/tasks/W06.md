# W06 — PDF 编辑器：新的基础编辑、基础/专业同一实例无缝切换、缩略图整理页面（D4，以及 PDF 的 D6 D9 D11）

先读 `tasks/_EDITOR.md`（编辑器 owner 共同清单 A–E），本文件只写 PDF 的特殊情况。

## 用户看到什么（完成后）

- 打开 PDF，顶栏页签是「编辑 | 专业编辑」（W01 负责页签本身）。
- **编辑**（基础）：画面就是 PDF 页面。编辑栏没选中东西时显示这些工具，带图标和文字：

  | 工具 | 行为 |
  |---|---|
  | 高亮 ▾ | 选颜色后拖选文字 |
  | 下划线 | 拖选文字 |
  | 删除线 | 拖选文字 |
  | ✓ 打勾 | 点哪放哪，可拖动、缩放、删除 |
  | ✗ 打叉 | 同打勾 |
  | 加文字 | 点哪写哪，用来填表 |
  | 签名 | 手写或打字；存下来，下次一点就放 |
  | 画笔 | 手绘 |
  | 便签 | 便签批注 |
  | 查找 | 全文查找 |

  - 选中一个批注时，编辑栏变成它的属性：颜色、透明度、删除。加文字的批注用统一文字栏（`00-dispatch.md` §4，只出做得到的项）。
  - 撤销、重做在顶栏。
- 左侧是页面缩略图：鼠标移到一页上，出现「旋转」和「删除」；拖动缩略图可以排序。
- 没有提取页、插空白页、合并 PDF，也没有旧版那个工具面板（「页面」抽屉）。
- **专业编辑**：EmbedPDF 官方完整界面，和基础编辑是**同一个**查看器实例、同一份文档。切换时只显示或隐藏工具，没有「正在切换」，不重新载入，页码、缩放、未保存的批注都在。
- 全程只有一个缩放控件。截图里右下角 100% 和工具栏 90% 是两个，要合成一个。
- 改动存成标准 PDF 批注（Acrobat、Preview、Chrome 都能看到），自动保存成同一份 PDF 的新版本。基础和专业两页顶栏都显示保存状态。
- 素材库里的图片或签名，点一下或拖进页面，就成为图章批注。
- 深色主题下，工具栏、缩略图栏、页面之间的底色是深色；PDF 页面本身保持白色。

## 已知事实

- [读码] 现状：
  - 基础 = 我们自己画的 `PdfStage`（旧核），配 `toolbox`「页面」（`PdfControls`：加空白页、合并、查找、批注入口）和 `PdfContextToolbar`（旋转、前移、后移、提取、删除本页）。
  - 专业 = `PdfNextStage`（`@embedpdf/react-pdf-viewer@2.15.0`，配置在 `pdf-pro-config.ts`，其中 `disabledCategories` 关掉了文件类命令）。
  - 两者靠 `ModeSwitchGate` 交接字节，这就是「正在切换到专业编辑…」的来源。专业模式的改动经 `saveAsCopy()` 拉回字节，再换进旧核。
- [读码] `pdf-next-facade.ts`：新核**不能把页面旋转写进文件**（只有视图旋转），也没有加空白页的 API。旋转写入文件需要另走字节级操作（现有 `pdf-operations.ts` 或 PDFium 引擎接口），写入后重新载入。
- [读码] 其它依赖 PDF 模块的地方：
  - `LibraryPdfReader.tsx`、`WorkspacePdfCover.tsx`（W05 的库预览和封面，用 `pdf-next-runtime` / `pdf-engine-host`）
  - `collab/adapters/pdf.ts`、`collab/adapters/use-pdf-collab.ts`（归你）
  - `doc-editors/doc-family-commands.ts` 里的 `buildPdfCommandSurface`（文件不归你：新建 `media-editors/pdf-command-surface.ts`，PdfRoute 切过去）
  - `quick-actions/catalog.ts`、`client-editor-adapters/registry.ts`（只读；不许破坏它们的 import）
- [实测，操作员截图] 专业页工具条最左有一个「文档 + 齿轮」图标。确认它点了有没有作用：没作用就在配置里关掉；有作用就保留。
- [实测] 保存缺陷：同一会话第 2 次及以后的保存没有成为新版本（W04 修内核）。你要保证 PDF 路由在 W04 修完后，保存协议逐条通过。

## 要做

1. 读 EmbedPDF 2.15 的 snippet / react-pdf-viewer 能力（`node_modules/@embedpdf/*`）：
   - 能否在同一实例上运行时隐藏或显示官方工具栏和侧栏。
   - 能否拿到 registry / plugins 来驱动批注工具（highlight、underline、strikeout、ink、freeText、stamp、note）和查找。
   - 缩略图能否自定义。
   写下可行方案（journal），选最直接的那条。
2. 基础编辑重建在同一个查看器实例上：
   - 官方 UI 隐藏，我们的工具走共享编辑栏（`contextToolbar` 和编辑栏空态的文档动作，或 W02 的抽屉按钮机制；工具是常用的，要直接显示在栏上）。
   - ✓ / ✗ 用矢量图章或 ink，必须是标准注释。
   - 签名：画板或打字生成图片；存到用户本地（localStorage，按用户 id 区分），以后一点即用。
3. 缩略图栏：旋转写进文件、删页、拖动排序，都要能撤销；协作只读时禁用。
4. 删除旧基础面：`PdfStage`、`PdfControls`、`PdfContextToolbar`、旧核里只服务被删功能的模块，以及 `ModeSwitchGate`（PDF 是唯一用户）、合并 PDF、加空白页、提取页。
   - 删之前查清谁在 import（只在 `src/` 内限定搜索）。
   - 被删行为的测试一并删掉或改写，交付里逐条说明。
5. 保存：
   - 只有一份文档实例，改动后自动保存走 doc-io（`pdf-library-save.ts`）。
   - 保存状态在两页都显示；字节从查看器取，可以用 `saveAsCopy()` 或引擎导出。
   - W04 交付后，按 §5 逐条在浏览器里跑：基础编辑加高亮、✓、文字；专业编辑加形状；关闭、重开都在，并且在别的 PDF 阅读器里也能看到（下载后用 `pdfjs` 以外的方式校验，例如 python `fitz`，没有就读 `/Annots`）。
6. 素材 adapter：接受图片素材，主动作 = 作为图章插到当前页中央。拖放时放到落点。
7. 深浅两档：查看器主题跟随站点（`pdfProTheme` 用 `usePluginTheme` 的 theme），页面保持白色。截图到 `evidence/W06/`。
8. 只留一个缩放：外壳右下角的缩放与查看器缩放二选一并保持同步。专业页官方工具栏里有缩放时，外壳那个隐藏。
9. agent 指令面：`pdf-command-surface.ts` 只暴露新能力，包括加高亮、加文字、打勾、旋转页、删页、下载、保存。
10. 文案写进 `editor-overhaul-copy-w06.ts`。测试：新能力的单元测试 + jsdom 判据「基础与专业同一实例、切换不出现 `data-mode-switch-pending`」。
