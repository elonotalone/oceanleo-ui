# W05 — 库页：类型名是素材类别、文档卡片直接显示标题和开头、卡片跟随主题（D5 D8 D6 库部分）

## 用户看到什么（完成后）

- 「我的库」的 Type 筛选菜单里是素材类别，没有一个「editing」/「编辑」：
  - 全部、视频、网站、演示文稿、文档、表格、图片、PDF、音频、视频画布、3D 模型、游戏
  - 英文：All / Video / Website / Presentation / Document / Spreadsheet / Image / PDF / Audio / Video canvas / 3D model / Game
  - 其它语种同理。
- 没有「设计画布」这一类了，它并进「图片」（10-22 的决定）：筛「图片」时能看到原来的设计画布素材，卡片下方小字也是「图片」。
- txt、md 以及所有文档类型的卡片：
  - 打开库就**直接**看到标题和开头几行，像截图里「备案表单修改与提交清单」那样的文字卡片。
  - 不转圈，也不显示渲染出来的整页图片。
  - 被编辑器保存过的文档（截图里的 notes.txt、「需签字盖章页清单」）同样如此。
- 深色主题下库的卡片、筛选菜单、空态都是深色，没有白底卡片。

## 已知事实

- [读码] `library-editor-category.ts` 的 `PRESENTATION` 表里，每个 feature 有三个值 `[类型名, 编辑器名, 别名]`：
  - `LIBRARY_EDITOR_CATEGORIES.label` 用的是第 2 个（编辑器名，如「视频编辑」）→ 筛选菜单因此带「editing」。
  - 卡片小字用第 1 个（类型名）。
- [读码] `design_canvas` 仍是 `ADVANCED_CAPABILITY_MATRIX` 的一行。
- [实测，生产库只读] 两张卡片转圈、两张正常，差别在 renditions：
  - 转圈的 `notes.txt`（txt）和「需签字盖章页清单」（md）的当前版本，`preview`、`thumbnail` 都是 **PNG**——编辑器保存时渲染的整页图。
  - 正常显示文字的 `upload-400-probe`（txt）和「备案表单修改与提交清单」（md）从没被编辑过，`preview`、`thumbnail` 都是**源文本本身**（text/plain、text/markdown）。
- [读码] `document-shelf-cover.tsx`：
  - 有 OOXML 内嵌缩略图就用图。
  - 否则取源文本前 64KB 生成摘要（`excerptFromText`），抓取期间显示「正在读取内容预览」。
  - 颜色写死成 `bg-white` / `text-stone-*`（深色下是白卡）。
  - 卡片用哪种封面由 `workspace-library-thumbnail.tsx` 决定。
- [读码] backend `ArtifactContentInput.metadata` 可以存任意 JSON；上传走 `app/typed_uploads.py`。
- 摘要字段的约定（`00-dispatch.md` §6）：`meta.text_excerpt`，≤600 字，去掉 markdown 记号后的前几行。
  - 上传时由你在后端填。
  - 编辑器保存时由 W08 经 W04 的透传填。

## 要做

1. 类型名：
   - 筛选菜单和卡片都用类型名；`design_canvas` 在库层面归一到 `image_editing`（只改读与展示，不改写存量数据）。
   - URL 里旧的 `?category=design`、`design_canvas` 继续能用，映射到图片。
   - 检查全部 17 语的类型名都有译文；缺的写进 `editor-overhaul-copy-w05.ts`。
2. 文档卡片：
   - 文档类型（document，以及 txt / md / docx 来源）的项一律走文字卡片，**永不**等待或显示 PNG 的 preview / thumbnail。
   - 标题立即渲染。摘要优先读 `meta.text_excerpt`；读不到再取源文本（≤64KB），抓取期间标题照常显示、摘要位置留空，不放「正在读取」的转圈。
   - docx 没有摘要字段时：现有的 OOXML 内嵌缩略图仍可用；如果你判断文字卡片更合适，就用 `extractDocumentCoverExcerpt` 的结果，统一成文字卡片。
3. 上传时存摘要：
   - 在 `typed_uploads.py` 里，txt / md（以及能便宜取到正文的 docx）上传时计算 `text_excerpt` 写进 revision metadata。
   - 加 pytest。改完在 journal 记一行，然后 `docker restart oceanleo-api`。
   - 确认库列表接口把 revision metadata 带到前端的 `LibraryItem.meta`（读码 + 浏览器核对）。不带的话，在你的后端文件里补，或写信号说明需要谁补。
4. 主题：
   - 库卡片（文字卡片、各类型卡片）、筛选下拉、空态，在深色下用站点 token，不许白卡。
   - 截图到 `evidence/W05/`，light 和 dark 各一张。
5. 浏览器验收：
   - 验收账号上传 `[W05]` 的 txt、md、docx。库里立刻是文字卡片。
   - 用文档编辑器各改一次、保存后回到库，仍是文字卡片且摘要更新（这一步依赖 W08；W08 没交付前写「待 W08」，之后再补一次）。
   - Type 菜单截图。
6. 测试：
   - 类型名映射（含设计画布归并）。
   - 文档卡片永不渲染 PNG 预览。
   - 有 `text_excerpt` 时不发起网络抓取。
   - 深色下没有 `bg-white`（源码断言或渲染断言都可以）。
