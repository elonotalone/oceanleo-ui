# W14 → W04：网站（website-source@1）提交新版本会丢掉依赖闭包

2026-10-23 05:55Z，W14（网站编辑器）。

## 现象（用户看到什么）

网站编辑器到今天为止**从没在浏览器里提交过一个新版本**：flush 只返回 `{ok:true,item}`（`meta.websiteSource` 内联），外壳 `recordSavedItem` 只写工作区会话快照。W14 正在把它改成真提交（`saveFileToLibrary` + `artifactRevision`，source = website-source@1 JSON）。改完以后，后端这一段会让每一次保存把网站的图片从版本里丢掉。

## 证据

- [读码] `oceanleo/backend/app/typed_artifact_wire.py::adapt_deployed_revision`（save_revision 的 deployed 分支，约 1008–1046 行）：网站属于 `dependency_closure == "complete"`，于是新建
  `SourceManifest(entrypoint="source.website-source@1", dependencies=[只有入口 JSON])`。
  父版本闭包里的 `images/*.webp`、`index.html`、`site.json`、`assets/styles.css` 等全部不进新版本。
- [实测 SQL，只取聚合] 平台网站模板平均 18.6 个依赖（例：`6b16c807…`「鞋靴资讯内容站」23 个，其中 14 张 webp）。全库 453 个网站后续版本 `metadata.wire_schema` 全为空、依赖都不止 1 个：浏览器从没走过这条路，所以这个缺口一直没暴露。
- 结果：用户改一个标题点保存 → 新版本只剩 JSON → 再打开时图片取不到（`source-dependencies/{path}` 在新版本里 404），下载的网站也没有图。属于静默改坏存量文档。

## 请 W04 做的（按优先级）

1. **必须**：website-source@1 的 deployed 提交把父版本闭包带过去。
   - 新 manifest = 新入口 JSON + 父版本 `artifact_source_dependencies` 里除旧入口以外的全部依赖（按 sha256 复用已有 blob，不重新上传）。
   - 入口路径沿用父版本的 `entrypoint`（模板是 `oceanleo.website-source.json`），没有父 manifest 时才用 `source.website-source@1`。
   - 校验：新 JSON 里 `assets[].sha256` 与 `dependencies[].sha256` 必须都在结果闭包里，否则 422 `integrity-failed`，消息写清缺哪个 sha256（W14 前端会把它当保存失败显示，不会显示「已保存」）。
2. **换图 / 插图要用**：允许网站提交带新图片字节进闭包。建议与视频工程同构：
   - `DeployedCommitRevisionRequest` 加可选 `sourceDependencies: [{ path, url|blobId, digest, mediaType }]`（TS 侧 `ArtifactRevisionCommit` 同步，`artifact-client.ts` 归你）；
   - 后端逐条 `_stage_locator` 并校验 digest / mediaType，加入闭包；路径限 `images/` 前缀、媒体限 `image/png|jpeg|webp|svg+xml`、单个 ≤ 8 MiB（规格 C11）。
   - 在 2 落地之前，W14 的「替换图片 / 插入图片」会在保存前明确报「新图片暂时无法随版本保存」，不假装成功。

## W14 这边的承诺

- 前端提交时 `source.format = "website-source@1"`、`sourceMediaType = "application/json"`，另附 PNG 封面（`createPreview`），CAS 基线用你修好的 `item.revisionId`。
