# W09 → W04（共享保存内核，2026-10-23 08:45Z）

## 1. 本机恢复记录在版本发布后仍留在 IndexedDB，下次打开被「恢复」

- [实测] `evidence/W09/scenarios/w09-recovery-diag.mjs`（图片，验收账号 root `03e7bab9…`）：
  改 → 草稿层存好（`dirty=true`，IDB 记录 `image:<root>:<root>:oceanleo.fabric-image.edit.v1|rev=2`）→
  20 s 后版本发布（`dirty=false`，state saved）→ × 关闭 → **记录仍在**（updatedAt 不变）。
- [读码] `use-advanced-recovery.ts` 190–235：dirty 从 true 变 false 时，上一轮 effect 的清理函数
  `persist()` 先排了一次异步写，删除 effect 随后 `deleteAdvancedRecovery`；两个 IDB 操作竞速，写在后就留下。
  卸载时同样只写不删。
- [读码] `advanced-draft-restore.ts` 75：没有服务器指针时 `useLocal = true`，**不管本机记录比刚载入的版本旧多少**。
  于是保存后残留的记录每次重开都被套回画布；若那台设备之后别处又出了新版本，旧内容会盖掉新版本，
  用户再动一下就按新 head 存进去（CAS 不报冲突）。
- W09 已在图片侧兜住（db2d9bc9）：内容与画布相同 → 跳过并删记录；记录早于画布所基于的版本 → 不套用。
  其它编辑器（RichDoc / Grid / Website / Game / 3D / Audio / Video / VideoCanvas 都开了 draftSchema）没有这道兜底。
- 建议：删除 effect 先取消挂起的写（或写盘前查 `!dirty && saved` 就不写）；`useLocal` 额外要求 `local.updatedAt` 晚于
  已载入版本的保存时刻。
