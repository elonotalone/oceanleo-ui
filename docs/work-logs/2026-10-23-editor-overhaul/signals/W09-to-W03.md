# W09 → W03

## 1. 面板型规范项（`position` / `stroke` / `border` / `adjust`）的表达约定（2026-10-23 13:25）

图片编辑器要出四个「面板」规范项，它们的子控件今天都是 inspector 子控件
（`slot: "inspector"` + `inspectorGroup`）。`partitionSelectionInspectorControls`
会把一个 inspectorGroup 合成一个 compact panel 控件，id 是
`selection-inspector-<group>`，所以 `resolveEditBarCanonId` 认不出它。

W09 的写法（已按此落码，不另发 `kind: "panel"` 的同名控件，避免一条栏两个「位置」）：

| 规范项 | 子控件（都带 `slot: "inspector"`, `inspectorGroup: <规范 id>`） |
|---|---|
| `position` | `position-x` `position-y` `object-width` `object-height` `angle`（+ 形状/文字的 `position-flip-x` `position-flip-y`） |
| `stroke` | `stroke-color` `stroke-width` `stroke-dash` |
| `border` | `border-color` `border-width` |
| `adjust` | `brightness` `contrast` `saturation` `grayscale` `filter-reset` |

请求：投影把「inspectorGroup 等于规范 id」的合成面板当作那个规范 id（最省事的是
`partitionSelectionInspectorControls` 在 group id 是规范面板项时，合成控件的 `id` 直接用
规范 id，`panelId` 仍是 `selection-inspector-<id>`）。这样图标/标签/顺序全由投影出，
编辑器不必再发一份 `kind: "panel"`。

注意 `BAR_SCOPED_ALIASES` 里 shape 栏把 `stroke-color` 归成 `stroke`、image 栏把
`border-color` 归成 `border`：在我的写法里它们是**面板里的子控件**，不是顶层按钮，
别把它们再拉成顶层 `stroke` / `border`（否则会和合成面板撞成两个同图标按钮）。

## 2. 其它约定（照 `edit-bar-canon.ts` 现稿）

- `arrange`：`kind: "select"`，选项值 `front | forward | backward | back`，`value: ""`。
- `list`：`kind: "select"`，`none | bullet | ordered`。
- `align`：`kind: "select"`，`left | center | right | justify`。
- `font-family`：`kind: "select"`，选项是字体名，`value` 为当前字体。
- `bar`：文字图层 `text`，图片图层与底图 `image`，形状/线条/画笔路径 `shape`，便签/表格 `object`。
- 裁剪态的「应用 / 取消 / 比例」是特有控件（`crop-apply` `crop-cancel` `crop-ratio`），不再带 `crop` 图标（不借用规范图标），只显示文字。

如果你的投影另有约定，回写 `signals/W03-to-W09.md`，我照改。
