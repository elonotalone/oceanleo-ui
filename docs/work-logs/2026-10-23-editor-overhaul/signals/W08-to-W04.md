# W08 → W04：文档的服务器草稿层（2026-10-23 08:40Z，R2 实测，验收账号）

非 W08 文件（`advanced-draft.ts` / `advanced-draft-controller.ts` / `use-advanced-autosave.ts`），只报现象与复现，不改。

1. **「已保存」可能只是草稿，不是 revision。** 打开文档后第一次改动直接走版本（staging×3 → revisions 200 → saved）；同一会话里第二次改动走草稿层：`POST /v1/database/upload`（`uploadAdvancedDraft`）→ saved，版本要等 `versionIdleMs` 20s 空闲或关闭时的 hand-off。
   - 关闭后约 9s hand-off 发出 revision（`close-after-draft-probe.mjs … docx 2`：rev 7=编辑1，rev 8=编辑2，08:37:25Z）。✔
   - 但关闭后 ≤9s 内重新打开、再整页刷新（`save-protocol.mjs`），编辑 2 只在草稿里：重开从草稿恢复（两处都在），却没有 revision，直到下一次编辑才随之发布（docx `2e894b64…`：07:55Z 一轮 3 次保存只有 rev 2/3，08:31Z 一轮又是 rev 4/5）。库卡片摘要在这段时间里停在旧版本。
   - 复现：`bash harness/mint.sh | OUT_DIR=/tmp/x THEME=light node harness/run.mjs evidence/W08/scenarios/save-protocol.mjs 2e894b64-3892-45d7-8c48-cdef0ecc9a8b docx`，再查 `artifact_revisions where artifact_id='2e894b64…'`。
   - 建议：从草稿恢复（`restoredDraft`）且草稿领先于 head 时，不等「本次访问有编辑」就排一次版本发布；或 take-back 时继承 hand-off 的待发布版本。
2. **每个编辑会话仍新建一个隐藏 root。** 草稿层 `uploadAdvancedDraft` → `uploadFile(registerAsset:false)` 每个会话产出一个 `…草稿` 的 `editorInternal` root（W08 txt 3 个会话 → 3 个 `[W08] notes 基线.txt-Edited草稿`）。不是每存一次一个，但 D13 清理清单需要把它们算进去，长期看应改走私有 staging。
