## 要做的

1. **出售/求购并成一个下拉**（值 出售 / 求购），样式由 W01 的共用件提供（你只传参）。整行读起来是「出售 ⌄ · 人工服务 ⌄ · 全部站点 ⌄」。求购时种类下拉改的是 `offer`，行为保持现有语义（见 `BayViewSwitch` 注释）。键盘、读屏可用。
2. **种类五个**（§5.1）：人工服务 / 现成文件 / 网站与软件服务 / 课程 / 其他。在 `bay-links.ts` 加 `other` 种类（`BAY_FEED_KINDS`、`canonicalBayFeedKind`、旧地址值继续可用：`?kind=asset` 等不得失效）。求购侧也能选「其他」。
3. **每一类显示按这一类发布的东西**：
   - 后端：出售侧 `listing_kind` 生效（I-10）：`service` = `listing_kind` 为 service 或空；其余等值匹配；`consult`、`help` 只在人工服务（或不传）时出现。补后端测试（`tests/test_bay_feed.py` 或新文件）。
   - 人工服务：信息流传 `listing_kind=service`。
   - 其他：信息流传 `listing_kind=other`。
   - 网站与软件服务：`BayAppShelf` 在现有 `bay_apps` 之后，接上卖家按「网站与软件服务」发布的条目（信息流 `listing_kind=app`），同一种卡片网格/列表风格；两边都空才显示空态。
   - 课程：`BayLessonShelf` 同理接上 `listing_kind=lesson`。
   - 现成文件：素材库的「来源」下拉加第一项「卖家在售 / From sellers」，列卖家按现成文件发布的条目（`listing_kind=digital`）。默认来源规则：有已发布的卖家现成文件时默认它，否则保持现在的默认。
4. **筛选的字**（§5.2）：站点「全部站点」；素材库各下拉的「全部」带名词；来源「我的」→「我上传的 / My uploads」；英文界面不能出现两个都叫 Type 的键（种类下拉现在只显示值，自然解决，核对一遍）。
5. 右侧栏 `PanelBrowse.tsx` 同步；它的搜索提示改成不列旧种类名（如「搜索 LeoBay」）。
6. 测试：`tests/bay3-page.test.mjs`、`tests/bay5-panel.test.mjs` 等被你打红的改绿；新增覆盖「出售/求购下拉」「五个种类」「每类传对 listing_kind」的测试（建议 `tests/lbp-w02-browse.test.mjs`）；后端测试绿。
