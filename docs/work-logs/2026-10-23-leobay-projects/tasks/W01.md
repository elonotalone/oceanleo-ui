## 要做的

1. 两份下拉的触发键都改成 §5.2 的样子：只显示当前值（选中项 label，或 `allLabel`）；`label` prop 不再画在键上，改作 `aria-label` 和菜单的读屏名；选了具体值时边框加深；高度字号对齐页头搜索框（`SEARCH_INPUT_CLASS` h-9）。两份外观必须一模一样（可以抽一份共同的 class 常量放在 `collection-chrome.tsx`，Bay 那份引用它；`collection-chrome.tsx` 不许 import bay 模块）。
2. 加可选 prop `defaultValue?: string`（两份都加）：值等于它时视作「未筛选」，不加深边框（给用 `"all"` 当全部的调用方用）。不传时以 `""` 为未筛选。
3. 菜单本身保持现有行为（键盘、搜索、计数、禁用说明），选中项前加一个勾，视觉与新按键协调。
4. `src/shell/menu-select.tsx`：把父放的占位换成正式实现，**props 不变**（I-1）。外观：一整条表单选择条（宽度随容器，h-10，圆角 xl，浅灰边，白底，左侧当前值、右侧下箭头），点开是与筛选菜单同一种白底圆角清单（可复用 `menuPlace` 思路、portal 到 body、键盘可用）；底下留一个视觉隐藏的原生 `<select>` 给测试和读屏改值（参考 `bay/form/BayMenuSelect.tsx` 的做法）。
5. 调用方传参改对（只改你边界内的文件）：所有 `allLabel` 都自带名词（「全部类型」等）；`Playground.tsx` 分区的值改成翻译过的名词（网站 / 应用 / agent / 提示词 这类——先在词典里找工作台别处已用的叫法，保持一致；英文首字母大写复数）；任何键上不会只剩「全部」。
6. 测试：更新/新增覆盖新外观与「只显示值」「defaultValue」「MenuSelect 键盘与原生 select 同步」的测试（建议新文件 `tests/lbp-w01-filter-select.test.mjs`）；跑与这些源文件相关的既有测试（`grep -l "CollectionFilterSelect\|BayFilterSelect\|collection-chrome" tests/*.mjs`），被你的外观改动打红的要改到绿（只做小范围精确替换）。
