# W10 交卷 · 项目页布局大改

W10（Sonnet 5.5，重派轮）。2026-10-23。只改了任务书边界内的文件；没有 push、没有重启容器、没有写库、没有开浏览器。

## 一句话

项目页从「顶栏通栏 + 四个页签的白板 + 通栏输入框 + 白底配置面板」改成「左列：白色圆角的**任务**卡片 + 紧贴其下的输入框（只在左列）；右列：整列都是**项目配置**，顶上是 动态 / 计划 / 资产 三张小卡片，下面是原来的 指令 / 连接器 / 专家 / 技能 / 自动化」。顶栏、输入框外层、右列外层都不再有白底，白色只剩一张张卡片。

## 1. 新布局（桌面 ≥1024px），从上到下、左到右

```
页面底色（奶白）
┌──────────────────────────────────────────────────────────────────────────┐
│ 项目 / 📁 项目名   [协作·可编辑]   ☆ 星标   删除   [邀请]     ← 顶栏：直接坐在底色上 │
├────────────────────────────────────────────┬─────────────────────────────┤
│ ┌────────────────────────────────────────┐ │ 项目配置                      │ ← 右列整列：从顶栏下面
│ │ 任务                                    │ │ ┌─ 动态 ───────────────────┐ │   一直到页面底
│ │ 说明条 · 筛选行 · 任务列表              │ │ │ 最近 3 条        查看全部 │ │
│ │ （ProjectTasksTab 原样；卡片内部自己滚）│ │ └──────────────────────────┘ │
│ └────────────────────────────────────────┘ │ ┌─ 计划 [n] ────────────────┐ │
│ ┌────────────────────────────────────────┐ │ │ 待处理 · 进行中 · 已完成    │ │
│ │ 输入框（它自己的白框，外面没有白底）    │ │ │ 前 3 条              打开  │ │
│ └────────────────────────────────────────┘ │ └──────────────────────────┘ │
│            ↑ 只在左列宽度内                 │ ┌─ 资产 [n] ────────────────┐ │
│                                            │ │ n 个文件 · m 个文件夹 …   │ │
│                                            │ └──────────────────────────┘ │
│                                            │  指令 / 连接器 / 专家 / 技能 / 自动化 │
└────────────────────────────────────────────┴─────────────────────────────┘
```

- **顶栏**（面包屑、改名、星标、删除、邀请）：无白底、无下边线，坐在页面底色上；去掉了顶栏上多余的 `pl-14`（外壳的 `main` 已经为手机上的菜单键让位，之前叠了两份）。
- **左列**：`ProjectWorkspaceFrame` 现在把主区和 `bottom` 放进同一列（`data-project-workspace-column`）；右列是这一列的兄弟，所以输入框不可能伸到右列下面。主区是白色圆角卡片，标题「任务」，内容是 `ProjectTasksTab`（`{ projectId, canEdit }` 原样）。四个下划线页签没有了。
- **右列**：标题「项目配置」（只在桌面显示；抽屉自己有标题），只读成员多一条说明，然后是 `ProjectSideCards`（动态、计划、资产），然后是 `<fieldset disabled={!canEdit}>` 里原样的 `ProjectConfigEditor`（指令、连接器、专家、技能、自动化）。右列外层桌面端**没有任何面板**（透明、无边框、无阴影、无圆角），内部自己滚、铺满到底。
- **筛选行**（`ProjectToolbar`）也不再是一块白底带边框的板：控件自己带框，外面什么都没有（§5.3）。

## 2. 三张小卡片：内容与空态

三张卡都是共享的 `ProjectConfigCard`（`count` / `summary` / `addAction` / `openAction`），各自读真实接口、各自带弹窗（`ProjectModal`）。侧卡片放在只读 `fieldset` **外面**：只能查看的成员也点得开、看得到。任一弹窗关掉，三张卡一起重读（工作在计划里做了，动态里就会出现）。

| 卡 | 有内容时 | 空态（一句话 + 主操作） | 弹窗 |
|---|---|---|---|
| 动态 | 全员动态最近 3 条：头像首字 + 谁 + 句子 + 相对时间；底部「查看全部」 | 「项目里的任务、待办、资产和成员变化会显示在这里。」没有按钮（空的时候打开没有意义） | 默认尺寸（max-w-2xl），里面是 `ProjectFeedTab`，打开时选「成员动态」（`initialScope`，缺省仍是「与我相关」） |
| 计划 | 标题旁数字 = 待办总数；一行「待处理 a · 进行中 b · 已完成 c」；前 3 条（进行中 > 待处理 > 已完成 > 已取消，同状态保持接口顺序）；「+」添加；底部「打开」 | 可编辑：「还没有待办。把项目目标拆成可以逐条完成的步骤。」+ 主按钮「添加待办」→ 卡内出现一行输入，回车直接 `createProjectTodo`（`source_kind: manual`），建完卡片重读。只读：「还没有待办。有编辑权限的成员添加后会显示在这里。」没有按钮 | 宽弹窗（约 960px），里面是 `ProjectPlanTab`，可在弹窗里改 |
| 资产 | 标题旁数字 = 根层条目数；「n 个文件 · m 个文件夹」；最近改动的 3 个（文件显示大小、文件夹显示「文件夹」）；「已用 x / y」；「上传」小按钮；底部「打开」 | 可编辑：「还没有文件。上传项目资料，团队成员都能看到。」+ 主按钮「上传文件」→ 直接打开系统文件选择，传到根目录；配额不足（429）停止并提示服务端原话。只读：「还没有文件。有编辑权限的成员上传后会显示在这里。」没有按钮、没有上传框 | 宽弹窗，里面是 `ProjectAssetsTab` |

读取中：骨架；失败：一句话 + 「重试」；已有内容时被通知重读是静默的（不闪骨架）；上一次读取失败后被通知重读会先显示「读取中」，不闪一句还不成立的空态。

**弹窗尺寸**：`ProjectModal` 新增可选 `size="wide"`：`max-w-[60rem]`（960px），高 `min(52rem, 100dvh − 2rem)`，正文区自己滚；不传仍是原来的 `max-w-2xl / max-h 44rem`。

## 3. 窄屏（<1024px）

- 主区全宽：任务卡片 + 输入框；顶栏右侧出现「项目配置」按钮。
- 右列收进右侧抽屉（宽 `min(22.5rem, 100vw − 2rem)`，页面底色 + 左边线 + 阴影，**不是白板**），抽屉自己的头部写「项目配置」+ ×，里面卡片顺序和桌面一样（动态、计划、资产、指令、连接器、专家、技能、自动化），内边距 16px。
- 抽屉里点开动态/计划/资产弹窗：弹窗在抽屉之上（z-[1000]）。**Esc 只关最上面那一层**：弹窗在，Esc 只关弹窗、抽屉留着；再按一次才关抽屉（之前抽屉与共享 Modal 都在 `document` 上听 Esc，会一起关）。
- 弹窗里的页签自己开的对话框（待办编辑、重命名、删除确认）：Esc 不再连外层弹窗一起关、草稿不丢；对话框自己处理 Esc（W11 已在两个页签里做了）照样收得到。

## 4. 翻译

`src/i18n/ui/messages/lbp-w10-copy.ts`：103 条 × 16 语（zh 键即值），都是词典里**原本就没有译文**的项目页文案（英文界面直接显示中文）：项目配置、动态、资产、专家、自动化、邀请、待办、文件夹、指令/连接器/技能的说明句、各类加载/保存/删除提示、只读说明、输入框占位……，加上右列新卡片的词、动态事件句子的 10 个模板、指令模板名。已有词条没有重定义；与基础英文表不冲突（测试里逐条核）。

两处改动是为了让译文说得对：
- `addAction` 的 `tt("添加{title}", { title: tt(label) })`：原来把中文卡片名直接塞进句子，英文界面是「Add 指令」。
- 动态里的「邀请」标签（名词）和顶栏的「邀请」按钮（动词）是两个意思，标签的中文原文改成「项目邀请」。

动态里的事件句子（「任务“…”状态为 running」）是后端 `activity_plan.py` 写死的中文模板，后端不给结构化字段。`ProjectSideActivityText.ts` 按同一批模板认回来再翻（含状态码、角色、后端自己写的「未命名…」兜底词）；认不出来的原样显示，不丢信息。

## 7. 没做完的 / 已知限制

- **没有开浏览器**（未批准），所以没有肉眼看过页面。版面几何用 jsdom 量（谁包着谁、类名），卡片行为用真渲染（编译台）验。
- **`src/theme/ui.css` 需要重编**：门户读共享 UI 编译好的 `ui.css`，`project-workspace.tsx` 里新用到的 Tailwind 类（`lg:bg-transparent`、`lg:border-0`、`lg:-mx-1`、`lg:p-0`、`px-4 pb-4`、`max-w-[60rem]`、`h-[min(52rem,calc(100dvh-2rem))]` 等）在重编前不会生效。`theme-artifact-in-sync` 在我动手前的 HEAD 上就是红的（别的 owner 的类名同样没编）。我没碰这个产物（不在边界、多 owner 并发）。**请父 agent 最后 `pnpm build:css` 并提交 `src/theme/ui.css` / `globals.css`。**
- 门户侧的卡片类名由门户自己的 Tailwind 编译，不受影响。
- 动态卡与「查看全部」弹窗读 `scope=members`（全员，是 `mine` 的超集）；`ProjectFeedTab` 单独使用时缺省仍是「与我相关」。
- 后端动态句子仍是中文模板（见 §4）；建议后端以后随句子带结构化字段（事件类型、标题、状态码），门户的模板识别就可以删掉。
- 共享 `Modal` 的 Esc 仍是「任何一层 Esc 都关」。我只在 `ProjectModal` 里给「自己内部的嵌套对话框」加了守卫；`ConfirmDialog` 这类 portal 出去的共享 Modal 叠在 `ProjectModal` 上时，两层还是会一起关（共享 Modal 的堆栈问题，不是本任务）。
