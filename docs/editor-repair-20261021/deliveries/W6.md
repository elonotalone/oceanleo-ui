# W6 delivery — video, audio, PDF, chart, 3D record a person edit

## Root causes

W2 already refuses autosave unless `userMutationGeneration > 0`. Video, audio, PDF, chart, and 3D still marked `dirty` (and bumped revision) on load, hydrate, remote collab, export URL rewrite, and draft restore, but never called `recordUserMutation`. A person trim / 「加节点」 / annotation / chart mutate / 3D gizmo therefore left generation at 0, so autosave never ran.

## Fix

Each owned editor exports a tiny named helper in the same file (hooks are not importable). Person origins call `recordUserMutation(userEditItemKey(item))`. Load / hydrate / remote / silent replace / bootstrap origins return the current generation.

The live mutate / commit / markDirty paths call those helpers:

- Video timeline `applyEdit` after document inequality (`person-commit`; source-byte recovery is `hydrate`). Gesture commit, undo/redo, and local collab apply also record. Load, remote apply, export URL rewrite, and draft restore do not.
- Designcombo `commit` and convert / toolbar / undo / redo record as `commit`. The load effect and recovery restore pass `load`.
- Video canvas 「加节点」 and other local graph writes go through `applyVideoCanvasPersonCommand` / `person-command`. Hydrate and draft restore pass `hydrate`.
- Audio mutations record after a successful local operation (`local-mutation`). Playlist `bump` records for trim/delete/gain/hosted dirty; recovery restore passes `recovery-restore`. `use-audio-remote-apply.ts` was not edited.
- PDF mutation runner and snapshot restore record `local-annotation`. `replaceBytesSilently` records only when `markDirty !== false` **and** `personEdit === true`; collab silent replace does not pass that flag.
- Chart `mutate` and `applyHistoryDocument` record. `applyRemoteDocument`, load, and recovery do not.
- 3D `markDirty` records `local-dirty`. Bootstrap `setDirty` is wrapped as `bootstrap`. Draft restore uses `recovery-restore`.
