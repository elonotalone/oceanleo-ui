Date: 2026-10-21

## Root causes

1. Compact edit bar added live `position-x` / `position-y` / `object-width` / `object-height` with `placement: "primary"` for V3 geometry readback. The operator saw `X 502 Y 415` on the bar. Readback already exists as an sr-only probe on `FabricImageStage`.
2. `ImageRoute` mounted `ImageCanvasViewSwitch` (结构 / 皮肤). `designMode` was not consumed by the canvas.
3. `FabricImageAiPanel`, `image-cutout`, L4 chips, and command-surface AI entries offered 抠图 / 放大高清 / 人像精修 / 重新打光 / 扩展画面 / 全景延展 / Extra notes.
4. Stage overlay keyed off `editor.loading`. The source-load effect called `setLoading(true)` on every re-entry, including persist-related dep changes. Autosave then covered the canvas with 「正在载入对象化图片画布…」.

## What changed

- Primary toolbar builder (`buildFabricImageToolbarControls`) keeps crop / filters / layers. XYWH moved to inspector `placement: "more"`. Stage geometry probe unchanged.
- `ImageRoute` no longer mounts `ImageCanvasViewSwitch` or the AI drawer / 抠图 action. Dead `designMode` state removed. Chrome flags live in `imageRouteChrome`.
- Retired AI ids are gone from `IMAGE_AI_PANEL_CAPABILITIES`, `AI_CAPABILITY_ENTRIES`, L4 chips, and `imageAiCommandDefinitions`. `FabricImageAiPanel` deleted. Ordinary canvas panels remain.
- Overlay predicate `imageStageShowsSourceLoadOverlay` is `loading && !sourceReady`. Hook uses `isNewImageSourceSession(item.key, reloadNonce)` before `setLoading(true)`.
- Fabric `onDocumentChange` (object:modified / toolbar mutations that `commit`) calls W2 `recordUserMutation`. Hydrate `loadSnapshot` does not.
