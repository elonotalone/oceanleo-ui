# W5 delivery — grid + deck record a person edit

Date: 2026-10-21
Repo: `/root/projects/oceanleo-ui` `main`

## Root causes

W2 already refuses autosave unless `userMutationGeneration > 0`. Image and rich documents call `recordUserMutation`. Grid, native deck, and hosted PPT only set `dirty` / bump revision:

- Grid `bumpHistory` is the local write choke (`onWrite`, toolbar, undo/redo, convert, import) but never recorded a person mutation. `createGridCollabBinder` `onActivity` also sets dirty, including remote activity.
- Native deck `commit` / `endGesture` / `undo` / `redo` set dirty after a document inequality; `applyRemoteDeck` (「别人的改动」) does the same. Load can also set dirty when a server draft is present.
- Hosted PPT records dirty from a `message.type === "dirty"` echo and from recovery `restore`. Init is already gated by opened-content identity; restore still marked dirty without a person edit this visit.

So a real grid or deck edit never opened autosave (fail-closed). Operator rule: autosave only after a person changes the work, every editor.

## Fix

Named helpers in the owned files call `recordUserMutation(userEditItemKey(item))` / `handoffItemKey(item)` only on the person path:

- Grid: `applyGridUserEditSession(item, "person-write")` from `bumpHistory`. `onActivity` uses `"collab-activity"`.
- Native deck: `applyDeckHistoryWriteIfChanged` from `commit` / `endGesture` after `deckDocumentsEqual` fails; undo/redo use `"local-history"`. Remote merge uses `"remote-collab"`. Server-draft load uses `"load"`.
- Hosted PPT: `applyHostedDeckUserEditSession({ kind: "dirty" })` after the opened-content identity check, `dirty === true`, source present, init applied. Recovery restore uses `kind: "restore"`.

`user-edit-session.ts` was imported only, not edited.
