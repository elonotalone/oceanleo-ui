# W2 delivery — autosave only after the person edits

## Root causes

`AdvancedPersistenceController.observe` (and the draft delegate) scheduled a flush whenever `dirty` was true and the revision changed. Editors bump those during load (Fabric `setLoading(true)` + scene hydrate; Umo empty document). Autosave then ran without a person changing the work: the image stage painted 「正在载入对象化图片画布…」 again, and documents tried to publish a blank or wrong-MIME file.

The live `observe({ revision, dirty })` call is `use-advanced-autosave.ts`. Dirty-from-load and dirty-from-typing looked the same.

## Fix

- `observe` schedules only when `userEdited === true` or `userMutationGeneration > 0`. Omitted `userEdited` is false. Explicit `flushLatest` / retry / integrity-failed-not-retryable are unchanged.
- Shared session `src/shell/user-edit-session.ts`: `recordUserMutation(itemKey)` / `userMutationGeneration(itemKey)` / `resetUserMutation(itemKey)`. Workbench `syncOpenUserEditItem` zeros generation when the open item changes.
- `useAdvancedAutoSave` passes `userEdited` from that generation. `SelectionCommandGate` records successful user commands (`update` / `commit` / discrete). `origin` `remote` / `collab` / non-`user` does not.

W1/W3 import:

```ts
import { recordUserMutation } from "../user-edit-session";
// image-editor: from "../user-edit-session"
```

Call `recordUserMutation(item.key || item.id)` when the person types or object-modifies. Do not invent a second autosave flag.
