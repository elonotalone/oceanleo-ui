# W5 — grid + deck record a person edit

Read `/root/projects/oceanleo-ui/docs/editor-repair-20261021/_COMMON.md` in full.

W2 already gates autosave on `userMutationGeneration > 0`. Image and rich documents already call `recordUserMutation`. Grid, native deck, and hosted PPT do not, so a real edit never autosaves (fail-closed). Operator rule: autosave only after a person changes the work, **every** editor.

## What to call

```ts
import { recordUserMutation, userEditItemKey } from "../user-edit-session";
// GridUniverStage / DeckHostedRoute: from "../user-edit-session"
recordUserMutation(userEditItemKey(item));
```

Call it when the **person** mutates. Do not call it on load, hydrate, collab remote, recovery restore, or save success.

### Grid

`bumpHistory` is the local write choke (`onWrite`, toolbar `runControl`, undo/redo, convert, import). Call `recordUserMutation` there.

`createGridCollabBinder` `onActivity` is collab activity (including remote). It may `setDirty(true)` but must **not** record a user mutation.

### Native deck (`use-deck-editor.ts`)

Record on the history commit path (`setDirty(true)` after a document inequality in the apply/endGesture/undo/redo functions around the existing local-history writes).

The collab apply that comments 「别人的改动」 (`setDirty(true)` after remote merge) must **not** record.

Load effect starts with `setDirty(false)` — leave that alone.

### Hosted PPT (`DeckHostedRoute.tsx`)

Copy the Umo pattern in `RichDocHostedRoute`: on `message.type === "dirty"` with `dirty === true`, after the opened-content identity check and after init is applied, call `recordUserMutation(handoffItemKey(item) or userEditItemKey(item))`.

Do not record on recovery `restore` that only marks dirty.
